🎓 ネタばらし｜なぜ漏れた？ どう防ぐ？

今日見つけた漏洩は、すべて実際の情報漏洩でよくある原因です。 共通点は「ブラウザに届いた情報は、利用者からはすべて見える」ということ。

#問題点どう漏れたか守り方
1HTMLコメントの消し忘れ「ソースを表示」で、コメントの中の仮パスワードが読めたコメントやメモをHTMLやJavaScriptに残さない。公開前に確認して消す。秘密はソースに書かない。
2robots.txt を隠し場所だと思ったrobots.txt に書いた管理画面のURLへ、誰でも直接開けたrobots.txt は検索結果に出さないお願いであり、鍵ではない。重要なページはログインで守る。
3接続の合言葉を JavaScript に書いたほかのサービスへ頼む窓口（API）の合言葉が、ページといっしょに届く JavaScript に書いてあった。検証の「ソース」で開くと読めた合言葉（APIキー）はサーバーに置く。ブラウザへ送る JavaScript には書かない。ブラウザはサーバーに頼み、サーバーが合言葉を使って窓口へつなぐ。
4文字の変換を、暗号化だと思ったatob で、ページに残っていた文字列が元の文章に戻った。鍵は要らなかった並びを変えただけでは秘密にならない。秘密そのものはサーバーで暗号化して保管し、ページには置かない。
5ブラウザの保存領域に秘密を置いたlocalStorage に保存したセッション情報が、検証画面から見えたlocalStorage や Cookie は、そのブラウザの利用者から読める。秘密やトークンは置かない。
6番号を変えると、他人のページが開いた名簿は3人だけだったが、URLの番号を変えると、載っていない人の情報まで見えた番号を知っているだけでは開けないようにする。1件ごとに、見る権限をサーバーで確認する。
もう一つの気づき： フラグの正解判定は、このサイトのJavaScriptの中で行っています。 判定プログラムを開くと、次のページのURLが書いてあることがあります。 本当のサービスでは、合っているかどうかの確認はサーバー側で行います。 ブラウザに届いたプログラムは、利用者から見えます。
時間があまったら： ミッション6のあと、チャレンジ問題を選べます。 チャレンジ問題を選ぶ
ホワイトハッカーの仕事：こうした“うっかり”を攻撃者より先に見つけて、 開発者に「ここ危ないですよ」と伝えて直してもらうこと。見つける力は、守る力です。
